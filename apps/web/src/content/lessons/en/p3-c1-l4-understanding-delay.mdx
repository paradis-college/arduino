### It's Like Closing Your Eyes! 🙈

```cpp
digitalWrite(13, HIGH);  // Light ON
delay(2000);             // Close eyes for 2 seconds...
                         // Can't see anything!
                         // Can't do anything!
digitalWrite(13, LOW);   // Light OFF (finally!)
```

<InfoBox type="warning">
  **During delay(2000):** Arduino is completely asleep! Even if you press a button 100 times, Arduino won't notice! 😴
</InfoBox>

<LessonChapter title="When Delay is a Problem! 🚨" id="when-delay-is-problem">

### The Button Problem 🔘

Imagine this: You want a light to blink AND respond to a button.

```cpp
void loop() {
  // Check button
  if (digitalRead(2) == LOW) {
    // Do something when pressed!
  }
  
  // Blink light
  digitalWrite(13, HIGH);
  delay(2000);  // Sleep 2 seconds - MISS BUTTON!
  digitalWrite(13, LOW);
  delay(2000);  // Sleep again - MISS BUTTON!
}
```

<GifStep
  stepNumber={2}
  title="Missed Button Press!"
  gifUrl="https://placehold.co/600x400/ef4444/white?text=Button+Missed!"
  alt="Button press missed during delay"
>
  **Problem:** While sleeping during delay, Arduino MISSES your button presses! It's like trying to talk to someone who's napping! 😴
</GifStep>

<InfoBox type="tip">
  **Think about it:** If delay is 2 seconds, and you press the button for 0.1 seconds, Arduino probably won't catch it! 🎯
</InfoBox>

</LessonChapter>

<LessonChapter title="When Delay is OK! ✅" id="when-delay-is-ok">

Delay IS fine for simple things:

### ✅ OK: Simple blinking light

```cpp
void loop() {
  digitalWrite(13, HIGH);
  delay(500);
  digitalWrite(13, LOW);
  delay(500);
}
```
This is fine if you don't need buttons or sensors!

### ✅ OK: Short delays

```cpp
delay(10);  // Just 10 milliseconds - super quick!
```
Short delays are usually OK because Arduino wakes up fast!

### ✅ OK: Startup message

```cpp
void setup() {
  Serial.begin(9600);
  Serial.println("Starting up...");
  delay(2000);  // OK here - just once at the start
}
```

<LessonChapter title="A Sneak Peek: millis()! 🔮" id="sneak-peek-millis">

There's a BETTER way! Instead of sleeping, Arduino can LOOK AT A CLOCK! ⏰

<GifStep
  stepNumber={3}
  title="The Clock Method"
  gifUrl="https://placehold.co/600x400/22c55e/white?text=Clock+Method"
  alt="millis() clock concept"
>
  Instead of sleeping, Arduino keeps checking the clock: "Has 1 second passed yet? No? OK, I'll check the button. Has 1 second passed? Yes! Time to blink!"
</GifStep>

### The Idea (Don't Worry About Code Yet!)

- **delay()** = Close eyes and count 🙈
- **millis()** = Keep looking at a clock ⏰👀

With the clock method, Arduino stays awake and can do MANY things!

<InfoBox type="info">
  **You'll learn millis() later!** For now, just remember: there's a way to time things WITHOUT sleeping! 🎉
</InfoBox>

</LessonChapter>

<LessonChapter title="You Did It! 🏆" id="summary">

### What you learned today:

- ✅ **delay()** makes Arduino SLEEP and do nothing else
- ✅ During delay, Arduino can **miss button presses**
- ✅ **Short delays** are usually OK
- ✅ **Long delays** can be a problem if you need to respond to things
- ✅ There's a better way called **millis()** (you'll learn later!)
