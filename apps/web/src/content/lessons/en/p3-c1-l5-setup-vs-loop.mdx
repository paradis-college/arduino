# setup() vs loop()

In this lesson, you'll understand the fundamental structure of every Arduino program - when code runs once and when it repeats! 🔄

<LessonChapter title="What You'll Learn" id="what-youll-learn">

- `setup()` runs **once** at startup
- `loop()` runs **repeatedly** forever
- Where to put initialization vs main logic
- Program flow visualization

  Every Arduino sketch MUST have setup() and loop() - understanding when each runs is essential for proper program structure! It's like the difference between getting ready for school (you do it once in the morning) and breathing (you do it all the time)! 🏫
</InfoBox>

<LessonChapter title="The setup() Function" id="setup-function">

### Runs Once at Power-On

`setup()` executes exactly once when:
- Arduino is **powered on** (connected to power)
- **Reset** button is pressed
- **New code** is uploaded

<InfoBox type="tip">
  **For kids:** `setup()` is like the morning when you get ready for school. You get dressed, pack your bag, eat breakfast - all just once. You don't get dressed over and over again all day! 🎒👕
</InfoBox>

### What Goes in setup()

- ⚙️ **Pin configuration** - pinMode()
- 📡 **Serial communication initialization** - Serial.begin()
- 📚 **Library initialization** - lcd.begin(), servo.attach()
- 🔢 **Initial values** for variables
- 🔧 **Hardware setup** that only needs to happen once

### Example

```cpp
void setup() {
  pinMode(13, OUTPUT);           // Configure pin 13 as output
  Serial.begin(9600);            // Start serial communication
  lcd.begin(16, 2);              // Initialize LCD screen
  servo.attach(9);               // Attach servo to pin 9
  
  Serial.println("Program started!");  // Startup message
}
```

<InfoBox type="info">
  **For parents:** setup() is the perfect place to put everything that needs to be done once. If something needs to be ready before the program starts working, it goes in setup().
</InfoBox>

<LessonChapter title="The loop() Function" id="loop-function">

### Runs Repeatedly Forever

After `setup()` completes, `loop()` runs continuously:

```
Start → setup() → loop() → loop() → loop() → loop() → ...
                    ↑_________|
                    (forever)
```

<InfoBox type="tip">
  **For kids:** `loop()` is like your breathing! You do it all the time, without stopping - breathe in, breathe out, breathe in, breathe out... Just like that, loop() runs code, then runs again, and again! 🌬️
</InfoBox>

### What Goes in loop()

- 📖 **Reading sensors** - analogRead(), digitalRead()
- 🔘 **Checking buttons** - if(digitalRead(...))
- 💡 **Updating outputs** - digitalWrite(), analogWrite()
- 🧠 **Main program logic**
- 🔄 **Anything that needs to repeat**

### Example

```cpp
void loop() {
  int sensorValue = analogRead(A0);  // Read sensor
  
  if (sensorValue > 500) {
    digitalWrite(13, HIGH);          // Turn LED on
    Serial.println("Sensor detected!");
  } else {
    digitalWrite(13, LOW);           // Turn LED off
  }
  
  delay(100);  // Small pause
}
// Then all this code runs again, and again...
```

### How Fast Does Loop Run?

Without delay(), loop() can run **tens of thousands of times per second**! It's very fast!

```cpp
void loop() {
  // This code runs THOUSANDS of times per second
  // if you don't have delay()!
}
```

<LessonChapter title="Common Mistakes" id="common-mistakes">

### Mistake 1: pinMode in loop()

```cpp
// BAD ❌ - wastes time reconfiguring every loop
void loop() {
  pinMode(13, OUTPUT);  // Don't do this!
  digitalWrite(13, HIGH);
}

// GOOD ✅ - configure once in setup
void setup() {
  pinMode(13, OUTPUT);
}
void loop() {
  digitalWrite(13, HIGH);
}
```

<InfoBox type="warning">
  Don't reconfigure pins in loop()! It's like getting dressed, undressing, and getting dressed again every time you take a step. You waste time and energy!
</InfoBox>

### Mistake 2: One-time actions in loop()

```cpp
// BAD ❌ - prints forever, flooding Serial Monitor
void loop() {
  Serial.println("Program started!");  // Appears thousands of times!
}

// GOOD ✅ - print once in setup
void setup() {
  Serial.begin(9600);
  Serial.println("Program started!");  // Appears once
}
void loop() {
  // Main logic here
}
```

### Mistake 3: Initialization in loop()

```cpp
// BAD ❌ - resets variable every cycle!
void loop() {
  int counter = 0;  // Always reset to 0!
  counter++;        // Becomes 1, but next cycle it's 0 again
  Serial.println(counter);  // Always prints 1
}

// GOOD ✅ - variable persists between cycles
int counter = 0;  // Declared outside functions

void loop() {
  counter++;
  Serial.println(counter);  // 1, 2, 3, 4, 5...
}
```

<InfoBox type="tip">
  **Ask yourself:** "Does this need to happen once or repeatedly?" Put the code in the appropriate function! 🤔
</InfoBox>

</LessonChapter>

<LessonChapter title="Complete Example" id="complete-example">

### Well-Structured Program

```cpp
// === GLOBAL VARIABLES ===
const int LED_PIN = 13;
const int BUTTON_PIN = 2;
const int SENSOR_PIN = A0;
int sensorReadings = 0;

// === SETUP - Runs ONCE ===
void setup() {
  // Configure pins
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  
  // Start serial communication
  Serial.begin(9600);
  
  // Startup message
  Serial.println("=== Arduino Started ===");
  Serial.println("System is ready!");
  
  // Confirmation LED
  digitalWrite(LED_PIN, HIGH);
  delay(500);
  digitalWrite(LED_PIN, LOW);
}

// === LOOP - Repeats Forever ===
void loop() {
  // Read the sensor
  sensorReadings = analogRead(SENSOR_PIN);
  
  // Check the button
  if (digitalRead(BUTTON_PIN) == LOW) {
    Serial.println("Button pressed!");
    digitalWrite(LED_PIN, HIGH);
  } else {
    digitalWrite(LED_PIN, LOW);
  }
  
  // Display sensor value periodically
  Serial.print("Sensor: ");
  Serial.println(sensorReadings);
  
  delay(100);  // Small pause for stability
}
```

<InfoBox type="info">
  **Good structure:** 
  1. Global variables at the top
  2. setup() with initializations
  3. loop() with main logic
  
  This makes code easy to read and understand!
</InfoBox>

</LessonChapter>

### Visualization: How the Program Runs

```
    ┌─────────────────┐
    │    STARTUP      │
    │   (power on/    │
    │    reset)       │
    └────────┬────────┘
             │
             ▼
    ┌─────────────────┐
    │    setup()      │
    │                 │
    │  • pinMode()    │
    │  • Serial.begin │
    │  • Initializations │
    │                 │
    │  (runs ONCE)    │
    └────────┬────────┘
             │
             ▼
    ┌─────────────────┐
    │    loop()       │◄────┐
    │                 │     │
    │  • Readings     │     │
    │  • Checks       │     │
    │  • Actions      │     │
    │                 │     │
    │  (REPEATS)      │     │
    └────────┬────────┘     │
             │              │
             └──────────────┘
             (infinite loop)
```

<LessonChapter title="Summary" id="summary">

In this lesson you learned: 🎓

- ✅ `setup()` runs **exactly once** at startup
- ✅ `loop()` runs **repeatedly forever**
- ✅ Put **initialization** in setup(), **main logic** in loop()
- ✅ **Don't reconfigure** pins or reinitialize libraries in loop()
- ✅ **Variables** declared in loop() get reset every cycle

### Quick Reference

| Function | When It Runs | What To Put |
|----------|--------------|-------------|
| `setup()` | Once at startup | pinMode, Serial.begin, initializations |
| `loop()` | Repeatedly forever | Readings, checks, main actions |
